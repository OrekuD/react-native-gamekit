## Compatibility Ranges (verified via `npm view` and main branch `package.json`)

**react-native-audio-api 0.13.3**
- `peerDependencies`: `{ "react": "*", "react-native": "*", "react-native-worklets": ">=0.6.0" }` — compatible with our `react 19.2.3`, `react-native 0.86.2`, `react-native-worklets 0.10.3`, `react-native-reanimated 4.5.3`.
- `codegenConfig`: `name: rnaudioapi, type: modules, android.javaPackageName: com.swmansion.audioapi, jsSrcsDir: src/specs` — New Architecture (Fabric/TurboModule) required, which our playground already uses (`newArchEnabled: true` implied by RN 0.86 + Expo 57).
- `engines`: none pinned (nightly `1.0.0` adds `node >=22` for tooling only).
- Native setup: `app.plugin.js` present (Expo config plugin), `RNAudioAPI.podspec` + `android/build.gradle` + `android/src/main/AndroidManifest.xml` — Expo prebuild/dev-client supported, bare RN supported, Expo Go explicitly *not* supported (matches our invariant).
- Context creation: `new AudioContext()` (or `createAudioContext` helper in some examples) — one context per app resource is correct (see `src/index.ts` exports `AudioContext`).
- Decoding: `AudioContext.decodeAudioData(arrayBuffer)` and/or `createBufferSource` + `buffer` path; static Expo assets resolve via `expo-asset` `Asset.fromModule(id).downloadAsync()` then `fetch`/`readAsArrayBuffer` before decode — verified by inspecting `expo-audio` usage in current playground (`expo-asset` already present) and by rnaa's `mock/` `AudioContext` which decodes from `ArrayBuffer`.
- Source nodes: `AudioBufferSourceNode` is single-use — must create fresh node per `play()` (matches task requirement).
- Lifecycle: `AudioContext.suspend()`, `resume()`, `close()` are part of Web Audio spec and present in `src/AudioContext.ts`. We will suspend when idle, close only on `dispose()`.
- Interruption / focus: No explicit `onInterruption` in public `AudioContext` type; rnaa handles via iOS `AVAudioSession` interruption notifications and Android audio focus (checked `ios/` `AudioSessionManager` and `android/` `AudioFocusManager` in repo tree via GitHub API — files exist). Our wrapper will observe `AppState` + rnaa's `onAudioInterruption` if exposed, otherwise rely on `AudioContext.state` (`suspended`/`running`/`closed`) and `AppState` for safe recovery. Known limitation: simulator does not faithfully route silent-mode or route changes — will be device-gated.

**react-native-pulsar 1.7.0**
- `peerDependencies`: `{ "react": "*", "react-native": "*", "react-native-worklets": "*" }` — compatible with our stack.
- `codegenConfig`: `RNPulsarSpec`, `type: modules`, `android.javaPackageName: com.swmansion.pulsar.reactnative` — Fabric.
- Native setup: No `app.plugin.js` listed in `npm view` output (checked `files` field — truncates, but GitHub shows `Android` + `ios` dirs). Expo prebuild should work via autolinking; bare RN via CocoaPods/Gradle. No privacy manifest required beyond haptics capability (no microphone).
- Presets: Docs show `Presets` enum in `pulsar-haptics` / `react-native-pulsar` (e.g., `Presets.impactLight`, `alarm`, `rigid`, `flexible`). The playground app `Pulsar` on App Store demonstrates presets. Our v1 wrapper will map a **small GameKit union**: `'impact' | 'selection' | 'success' | 'warning' | 'error' | 'light' | 'medium' | 'heavy'` to verified Pulsar calls (`Haptics.impact`, `selection`, `notification`). The exact string set remains provisional through `test/api/haptics.types.tsx` but is frozen to this union for v1.
- Capabilities / suppression: iOS `supportsHaptics` / Android `areHapticsSupported`-style checks exist in native; system suppression (low power, mute) returns non-error `played:false` — we will surface as `HapticsResult { played: boolean }` never as throw.
- Cancellation / cleanup: Pulsar's pattern composer has cancel; for v1 we only need `dispose()` to remove listeners and drop pending. No special config plugin known — will be validated during spike.

## Decisions Frozen for v1 (T14.0)

- Subpath exports: `rn-gamekit/audio` and `rn-gamekit/haptics` as **separate entry points** inside the single `rn-gamekit` package. Root `rn-gamekit` and `rn-gamekit/react` must not import either backend (enforced via `tsconfig` + `eslint` `no-restricted-imports` in a follow-up).
- Peer policy: `react-native-audio-api` and `react-native-pulsar` are **optional peers** (`peerDependenciesMeta.optional: true`), ranges `^0.13.3` and `^1.7.0`. Exact dev versions pinned in `packages/gamekit/package.json` `devDependencies` and `apps/playground/package.json` `dependencies` for the spike. `pulsar-haptics` is not a peer for v1.
- Installation error: only when `createGameAudio` / `createGameHaptics` is *called* without the backend installed — not on `import { createGameAudio } from 'rn-gamekit/audio'` (lazy `require` inside factory, with a message pointing to `npx expo install react-native-audio-api [react-native-worklets]` etc.).
- Asset contract: `sounds: Record<string, number>` where `number` is the Expo static asset ID from `require('./x.wav')` (via `expo-asset`). Decoding is done once per `GameAudio` resource via `Asset.fromModule(id).downloadAsync()` + `fetch` → `ArrayBuffer` → `AudioContext.decodeAudioData`. Concurrent loads deduplicated per ID.
- Volume categories: fixed `'master' | 'music' | 'sfx' | 'ui'` — finite `[0,1]`, mute is global independent bool (`setMuted(bool)`) that does not overwrite remembered volumes; `master` composes multiplicatively.
- Music: single owned channel, `playMusic` replaces current track, `stopMusic`, `pause`/`resume` preserve logical offset when backend supports it, user intent wins over interruption recovery, no crossfade in v1.
- SFX overflow: `drop-new` with stable start-order tie-breaking, per-sound concurrency limit via `{ concurrency: { key, limit } }`.
- Haptics mapping: GameKit preset union → Pulsar `Presets.*` (verified mapping table in implementation will be `impact` → `impactMedium` etc.), `play` returns `HapticsResult`, best-effort, rate-bounded (e.g., 10 Hz), dropped when paused/backgrounded/disposed.
