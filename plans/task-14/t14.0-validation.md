## Inspected Source — Exact APIs (pinned 0.13.3 / 1.7.0)

### react-native-audio-api 0.13.3 — AudioContext lifecycle

```ts
// src/core/AudioContext.ts
class AudioContext extends BaseAudioContext {
  constructor(options?: { sampleRate?: number /* 8000..96000 */ }) { /* creates AudioAPIModule.createAudioRuntime() + globalThis.createAudioContext(sampleRate) */ }
  async close(): Promise<void>   // (this.context as IAudioContext).close()
  async resume(): Promise<void>  // (this.context as IAudioContext).resume()
  async suspend(): Promise<void> // (this.context as IAudioContext).suspend()
  createMediaElementSource(handle: AudioTagHandle): MediaElementAudioSourceNode
}
// src/core/BaseAudioContext.ts
get currentTime(): number
get state(): ContextState // 'running' | 'suspended' | 'closed'
async decodeAudioData(input: number | string | ArrayBuffer, fetchOptions?: RequestInit): Promise<AudioBuffer>
async decodePCMInBase64(base64: string, sampleRate: number, channels: number, interleaved?: boolean): Promise<AudioBuffer>
createBufferSource(options?: { pitchCorrection?: boolean }): AudioBufferSourceNode
// + createBuffer, createGain, createBiquadFilter, createOscillator, etc.
```

* **Context creation:** One `AudioContext` per app resource is correct; `createAudioContext(sampleRate, audioRuntime)` is the native entry. `sampleRate` is optional, clamped by `AudioManager.getDevicePreferredSampleRate()` when omitted.
* **Decode inputs:** `DecodeDataInput = number | string | ArrayBuffer` — `number` is an Expo static asset ID (see below), `string` is a file path/URL, `ArrayBuffer` is raw PCM. Verified via `BaseAudioContext.decodeAudioData`.
* **Expo static asset resolution:** Verified path is `expo-asset`: `Asset.fromModule(id: number).downloadAsync() -> fetch(uri).arrayBuffer() -> context.decodeAudioData(arrayBuffer)`. `expo-asset ~57.0.8` is already a peer/dev dep. `src/api.ts` re-exports `decodeAudioData` for this path.
* **Source-node completion:** `AudioBufferSourceNode` is single-use; second `start()` throws `InvalidStateError: Cannot call start more than once`; `buffer` can only be set once (`InvalidStateError`). Completion is via `AudioEventEmitter` `'ended'` (`EventEmptyType`) and queue variant `bufferEnded: { bufferId, isLastBufferInQueue }`; loop variant `loopEnded`. Native errors reject the voice exactly once and are surfaced via `'ended'` cleanup.

### react-native-audio-api 0.13.3 — AudioManager (system interruption / route)

```ts
// src/system/AudioManager.ts
class AudioManager {
  getDevicePreferredSampleRate(): number
  async setAudioSessionActivity(enabled: boolean): Promise<void> // throws SessionActivationError with nativeCode/nativeDesc/nativeDomain on failure
  setAudioSessionOptions(opts: { iosCategory?, iosMode?, iosOptions?: IOSOption[], iosAllowHaptics?, iosNotifyOthersOnDeactivation? }): void
  disableSessionManagement(): void
  observeAudioInterruptions(param: AudioFocusType | boolean | null): void // AudioFocusType = 'gain' | 'gainTransient' | 'gainTransientExclusive' | 'gainTransientMayDuck'
  activelyReclaimSession(enabled: boolean): void // uses AVAudioSessionSilenceSecondaryAudioHintNotification + polling (experimental)
  observeVolumeChanges(enabled: boolean): void
  addSystemEventListener<Name extends SystemEventName>(name: Name, cb: SystemEventCallback<Name>): AudioEventSubscription // returns { subscriptionId, remove() }
  // + permissions, getDevicesInfo, setInputDevice
}
type SystemEventName = 'volumeChange' | 'interruption' | 'duck' | 'routeChange'
type SystemEvents = {
  volumeChange: { value: number }
  interruption: { type: 'began' | 'ended', shouldResume: boolean }
  duck: {} // EventEmptyType
  routeChange: { reason: 'Unknown'|'Override'|'CategoryChange'|'WakeFromSleep'|'NewDeviceAvailable'|'OldDeviceUnavailable'|'ConfigurationChange'|'NoSuitableRouteForCategory' }
}
```

* **Listener cleanup contract:** `addSystemEventListener` returns `AudioEventSubscription` with `.remove()` (and underlying `subscriptionId` as string passed to native). Verified via `src/events/types.ts` and `src/system/AudioManager.ts: addSystemEventListener` which delegates to `AudioEventEmitter.addAudioEventListener`.
* **Interruption payload:** `{ type, shouldResume }` where `shouldResume` indicates whether the system expects the app to resume; our recovery must check `type === 'ended' && shouldResume && sessionStatus === 'running' && appState === 'active' && !userMuted` before resuming.
* **Route change:** `reason` enum above; relevant for headset/speaker switches.

## Decisions Frozen for v1 (T14.0)

- Subpath exports: `rn-gamekit/audio` and `rn-gamekit/haptics` as **separate entry points** inside the single `rn-gamekit` package. Root `rn-gamekit` and `rn-gamekit/react` must not import either backend (enforced via `tsconfig` + `eslint` `no-restricted-imports` in a follow-up).
- Peer policy: `react-native-audio-api` and `react-native-pulsar` are **optional peers** (`peerDependenciesMeta.optional: true`), ranges `^0.13.3` (`>=0.13.3 <0.14.0`) and `^1.7.0`. `^0.13.3` does **not** authorize `1.x`; future `1.x` will be added as `^0.13.3 || ^1.0.0` only after testing. Exact dev versions pinned in `packages/gamekit/package.json` `devDependencies` and `apps/playground/package.json` `dependencies` for the spike. `pulsar-haptics` is not a peer for v1.
- Installation error: only when `createGameAudio` / `createGameHaptics` is *called* without the backend installed — not on `import { createGameAudio } from 'rn-gamekit/audio'` (lazy `require` inside factory, with a message pointing to `npx expo install react-native-audio-api [react-native-worklets]` etc.).
- Asset contract: `sounds: Record<string, number>` where `number` is the Expo static asset ID from `require('./x.wav')` (via `expo-asset`). Decoding is done once per `GameAudio` resource via `Asset.fromModule(id).downloadAsync()` + `fetch` → `ArrayBuffer` → `AudioContext.decodeAudioData`. Concurrent loads deduplicated per ID.
- Volume categories: fixed `'master' | 'music' | 'sfx' | 'ui'` — finite `[0,1]`, mute is global independent bool (`setMuted(bool)`) that does not overwrite remembered volumes; `master` composes multiplicatively.
- Music: single owned channel, `playMusic` replaces current track, `stopMusic`, `pause`/`resume` preserve logical offset when backend supports it, user intent wins over interruption recovery, no crossfade in v1.
- SFX overflow: `drop-new` with stable start-order tie-breaking, per-sound concurrency limit via `{ concurrency: { key, limit } }`.
- Haptics mapping: GameKit preset union → Pulsar `Presets.*` (verified mapping table in implementation will be `impact` → `impactMedium` etc.), `play` returns `HapticsResult`, best-effort, rate-bounded (e.g., 10 Hz), dropped when paused/backgrounded/disposed.
