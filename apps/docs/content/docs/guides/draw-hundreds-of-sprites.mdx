---
title: Draw hundreds of sprites
description: "Put repeated sprites in a SpriteBatch: one decoded sheet, one Atlas draw, fixed-capacity buffers."
---

When a game fills the screen with coins, enemies, or particles that share one sheet, individual sprite nodes get expensive. `SpriteBatch` draws them all in one `Atlas` call. This guide covers when to switch and how to set it up; the Sprite Field example in the playground (`src/screens/sprite-field`) is the live version.

## When to switch

- Fewer than a few dozen individually authored sprites: keep `Sprite` nodes. They're easier to read and fine for a stable cast.
- Many instances of one shared sheet (pickups, projectiles, tile details): use `SpriteBatch`.

The boundary is shared texture plus count. If the sprites share one sheet and the count grows with the scene, batch.

## 1. Decode the sheet once

Load the sheet through the asset store. Wait for readiness before mounting
the batch; keep the loading branch after your component's hooks:

```tsx
const assetsState = useGameAssets(definition.assets, { groups: ['gameplay'] });
if (assetsState.status !== 'ready') return null;
const coins = assetsState.assets.get(definition.assets.gameplay.coins);
```

## 2. Write instances per frame

Pass the renderer's commit and alpha shared values. The batch calls `select`
and `write` on the UI runtime, hides unused slots, and publishes the completed
buffers to Skia:

```tsx
<SpriteBatch
  scene="play"
  commit={frame}
  alpha={alpha}
  source={coins}
  capacity={64}
  select={({ current }) => {
    'worklet';
    return current.coins;
  }}
  write={(slots, coin, index) => {
    'worklet';
    slots.set(index, coin.frame, coin.x, coin.y, 0, 1);
  }}
/>
```

The scene snapshot in this example contains coins with `frame`, `x`, and `y`
fields. Capacity is the maximum number of slots, and the selected array sets
the active count. Keep capacity fixed for a mounted batch. The batch owns
buffer updates; no additional frame callback is needed. Its buffers are
reused, though selection and transform calculations can allocate temporary
values. The scene owns coin positions; the batch only presents them.

## 3. Keep the topology fixed

The batch node itself is stable; only the buffer contents change. That's the same rule as the rest of the renderer: build the tree once, update shared values. [Rendering](../engine-systems/rendering) covers the pattern, and [Sprite batching](../engine-systems/sprite-batching) has the full API contract including the transform elements (`computeSpriteRsxform`, `spriteAnchorWorld`, `spriteGroupCorrection`).

## Measuring

Whether batching helped is a measurement question, not a vibe. The [profiling harness](../advanced/profiling) shows draw cost per frame; compare before and after the switch.
