---
title: Camera coordinates
description: Convert between world, logical, and surface coordinates with the same pure functions the runtime uses — and keep pointer input aligned.
---

Camera math is one set of pure functions. The runtime, your game code, and your tests all call the same helpers, so a conversion written in a scene update can never drift from what the renderer draws.

## The three conversions

```ts
import { logicalToWorld2D, surfaceToWorld2D, worldToLogical2D, worldToSurface2D } from 'rn-gamekit/camera2d';

// World -> logical view (through the camera):
const logical = worldToLogical2D(worldPoint, camera, LOGICAL_VIEW);

// Logical view -> world (the inverse):
const back = logicalToWorld2D(logical, camera, LOGICAL_VIEW);

// World -> surface, composed with the resolved viewport:
const surface = worldToSurface2D(worldPoint, viewport, camera);

// Surface -> world (what pointer inversion does):
const world = surfaceToWorld2D(surface, viewport, camera);
```

`worldToSurface2D` and `surfaceToWorld2D` derive the camera's logical view from the resolved viewport's visible bounds, so they compose exactly the transform the renderer draws with. The round trip `surfaceToWorld2D(worldToSurface2D(p))` holds within the documented tolerance.

## The identity camera

The camera that reproduces the no-camera path is the camera whose center equals the logical view center, with zoom 1 and no rotation:

```ts
const identity = createCamera2D({
  center: { x: 160, y: 240 }, // the 320 x 480 logical view center
});
```

Games without a camera never touch this path at all; an explicit identity camera matches it exactly.

## Pointer alignment

`GamePointerInput` applies containment first (a `fit` letterbox begin is rejected before any conversion), then inverse-maps through the camera sampled with that native event on UI. Deferred and coalesced moves retain their event-time camera instead of reading a newer camera when RN receives them. Camera motion never cancels pointer ownership, and a hard cut never synthesizes touches. When a camera is configured but has not published its first valid value, new pointer begins are rejected.

The renderer's `camera` shared value contains an optional `CameraCut2D`. Conversion helpers take its inner `camera: Camera2D`, not the cut wrapper. Sample and narrow it on UI before converting; keep this mapping out of React render.

The [Camera Lab](https://github.com/OrekuD/react-native-gamekit/tree/main/apps/playground/src/screens/camera-lab) shows the crosshair: the world point from the pointer action renders exactly where you touched, through zoom, rotation, shake, and cuts.
