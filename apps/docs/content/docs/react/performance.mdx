The performance rules of Gamekit come from one sentence: the simulation is headless, and the UI thread only presents. This page is the React-side summary; [Performance model](../advanced/performance-model) is the full model, and [Profiling](../advanced/profiling) is how to measure.

## Interpolate, don't wait

At refresh rates above the simulation rate, the UI presents the same tick twice. Renderers should derive positions from `alpha` between the previous and current snapshot, not jump to the current one. The renderer guide shows the pattern:

```tsx
const x = useDerivedValue(() => {
  'worklet';
  const current = frame.value.current;
  const previous = frame.value.previous;
  const t = alpha.value;
  return lerp(previous.ball.x, current.ball.x, t);
});
```

## Keep the React tree fixed

Build the renderer's tree once from stable props. Per-frame data arrives as shared values, so Skia re-renders without React. A renderer that rebuilds nodes per frame defeats the design; the contract test in the Collision Lab enforces a fixed topology with stable keys.

## Batch what repeats

Many instances of one sprite sheet belong in a `SpriteBatch` (one `Atlas` draw), not in hundreds of `Sprite` nodes. Shared texture, fixed-capacity buffers, zero per-instance React. [Draw hundreds of sprites](../guides/draw-hundreds-of-sprites) shows the threshold and the setup.

## Threads and worklets

React renderer components configure the tree on the React Native runtime.
Their worklets project shared values on the UI runtime. Calls from those
worklets must use workletized helpers or supported runtime APIs; calling an
ordinary React Native runtime function directly can throw. An intentional
cross-runtime callback uses `scheduleOnRN` and must target a function defined
on the React Native runtime.

`GameView` keeps its frame worklet stable across ordinary React renders.
On each frame with UI-observation instrumentation disabled, the worklet performs no diagnostic
timestamp reads, diagnostic shared-value writes, or React Native callbacks.
Enabled observations report once per revision for the current observer;
replacing the observer starts a new observation lifetime without restarting
the simulation. This measures UI observation, not GPU presentation or FPS.
Updating instrumentation still mirrors its enabled flag at control frequency.

## Where the frame time goes

Simulation ticks commit snapshots; the renderer transforms and draws them. The three costs to watch are simulation work per tick (scene update), snapshot size (what gets deep-frozen and copied), and draw complexity (Skia work). Measure all three with the [profiling harness](../advanced/profiling) before optimizing any one of them.
