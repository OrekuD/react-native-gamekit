All components come from the `rn-gamekit/react` entry. This page lists what each one does and when you need it.

## GameView

The presentation surface. It borrows the session, starts it while mounted, pauses it when the app backgrounds, and hands your renderer the frame, alpha, and viewport shared values.

```tsx
import { GameView } from 'rn-gamekit/react';

<GameView game={session} renderer={MyRenderer} assets={assets}>
  <GamePointerInput game={session} action="steer" />
</GameView>
```

Props: `game` (required), `renderer` (required), `assets` (loaded assets), `camera2D` (an optional presented camera from `defineGameCamera2D`), `presentationKey` (forces a fresh renderer mount), `instrumentation`, `style`, and `children`. The renderer receives `frame`, `alpha`, `viewport`, `assets`, and (when a camera is declared) `camera` as shared values or stable props; see [How Gamekit uses React](./how-gamekit-uses-react).

## GamePointerInput

The touch adapter. It maps Gesture Handler events for one declared pointer action into the session's semantic input, handling ownership, cancellation, and coalescing. Mount it inside `GameView`, on top of the gameplay surface:

```tsx
<GamePointerInput game={session} action="steer" />
```

Props: `game`, `action` (a declared pointer action name), `instrumentation`. One instance per pointer action; secondary pointers are ignored until the owner releases. See [Input](../engine-systems/input).

## GameButtonPad and GameButton

The multitouch button surface. It maps every active pointer to the
measured bounds of a `GameButton` and flows press and release edges into
the session's declared button actions. Unlike `Pressable`, simultaneous
fingers on different buttons all register, so you can hold left and jump at
the same time.

The pad itself is an invisible full-surface overlay. It draws nothing and
its empty areas let touches pass through (`pointerEvents="box-none"`), so
you can render whatever React children you like underneath and position
each button anywhere on screen with ordinary styles.

```tsx
import { GameButton, GameButtonPad } from 'rn-gamekit/react';

<GameButtonPad game={session} hitSlop={12}>
  <GameButton action="left" style={styles.left}>{"\u2190"}</GameButton>
  <GameButton action="right" style={styles.right}>{"\u2192"}</GameButton>
  <GameButton action="jump" style={styles.jump}>Jump</GameButton>
</GameButtonPad>
```

Actions are not fixed. Each `GameButton` presses the button action name
you declared in `defineGame` — `left`, `right`, `jump`, `attack`,
`pause`, or any other string in `Record<string, { type: 'button' }>`. The
same primitive covers a GameBoy-style d-pad, AB buttons, and system
buttons: every zone is just a named button.

Props — `GameButtonPad`: `game` (required), `children` (one or more
`GameButton` elements plus any non-interactive art), `style` (layered over
the default full-surface overlay), `hitSlop` (extra hit area around every
zone), `testID`. Props — `GameButton`: `action` (a declared button
action name), `style`, `children`, `testID`, `accessibilityRole`. Each
button measures its own bounds on layout; sliding between zones reassigns
the pointer, release edges always fire, and unmount releases every held
action so no input outlives the pad. See [Input](../engine-systems/input).

## Sprite components

| Component | Purpose |
| --- | --- |
| `GameSprite` | A sprite driven by a scene snapshot via a `select` worklet; picks the clip from your game state (for example the current animation frame). |
| `Sprite` | A retained sprite: one full image or one sheet frame, with plain or shared-value props. |
| `SpriteBatch` | Many instances of one decoded sheet in a single Skia `Atlas` draw, with fixed-capacity UI-owned buffers. |
| `GameWorld2D` | A coordinate wrapper that applies the viewport transform to its children. |

The rule of thumb: `Sprite` for a modest number of individually authored sprites, `SpriteBatch` for shared-texture density. [Sprites](../engine-systems/sprites) and [Sprite batching](../engine-systems/sprite-batching) have the details; [Draw hundreds of sprites](../guides/draw-hundreds-of-sprites) is the hands-on version.

## Camera and layer components

| Component | Purpose |
| --- | --- |
| `GameLayer2D` | An ordered parallax layer inside `GameWorld2D`. JSX order is draw order; each factor scales only the camera center contribution. |

The camera itself is not a component: you declare it with [`defineGameCamera2D`](../engine-systems/camera2d) and pass it to `GameView` through the `camera2D` prop. See [Render layers](../guides/render-layers) for parallax in practice.

## Particle components

| Component | Purpose |
| --- | --- |
| `ParticleView` | A presentation-only Skia surface that draws a headless particle system. |

Pair it with `useParticlePresentation` to bind a `createParticleSystem` simulation to UI-owned buffers; see [Particles](../engine-systems/particles).

## Which components mount where

GameView and GamePointerInput belong in the game screen, once. Sprite components belong in the renderer, inside GameView. HUD headers and overlays are ordinary React Native views outside the canvas, and they must not sit inside the gameplay hit surface.
