# Game Definition and Session

> **Provisional.** The first runtime slice is implemented, but these names and
> shapes remain provisional until reference games validate them.

## Define the static game

`defineGame` remains pure: it validates and returns configuration without
starting time, loading assets, or allocating a live session. `defineScene`
infers the state returned by `create` and the renderer-specific snapshot.

```ts
import { createGameSession, defineGame, defineScene } from 'react-native-gamekit';

const definition = defineGame({
  viewport: {
    logicalSize: { width: 320, height: 180 },
    scale: 'fit',
    overflow: 'letterbox',
  },
  assets: [],
  input: {
    boost: { type: 'button' },
  },
  scenes: {
    play: defineScene({
      actions: ['boost'],
      create: () => ({ x: 0 }),
      update: ({ state, input, deltaSeconds }) => ({
        x: state.x + (input.button('boost').held ? 180 : 60) * deltaSeconds,
      }),
      snapshot: ({ state }) => ({ x: state.x }),
    }),
  },
  initialScene: 'play',
});

const game = createGameSession(definition);
```

`initialScene` is constrained to the keys of `scenes`, and session input calls
are constrained to the keys of `input`.

## Fixed-step session

`game.start()` starts an idle session and resumes a paused session.
`game.pause()` discards suspended wall time. `game.dispose()` permanently
stops the session and releases the scene. These operations are idempotent in
their applicable states.

The simulation uses a fixed 60 Hz step by default. A phone presenting at 60 Hz
and an iPad presenting at 120 Hz therefore advance the same number of gameplay
ticks over the same elapsed time.

Each update receives:

- readonly scene state;
- one immutable semantic input snapshot;
- a constant `deltaSeconds`;
- deterministic tick and elapsed-simulation values.

Each presentation frame contains `previous` and `current` snapshots plus an
interpolation `alpha`. The snapshot payload belongs to the renderer; the core
does not define a universal 2D/3D transform, camera, or material model.

## Skia GameView

```tsx
import { GameView } from 'react-native-gamekit/react';

<GameView game={game} renderer={MySkiaRenderer}>
  <MyStaticHud />
</GameView>
```

The Skia renderer receives shared `frame` and `surfaceSize` values. They update
without placing positions or tick counters in React state. Static React
children remain available for HUD and accessible controls.

`GameView` starts the externally owned session while mounted and pauses it on
cleanup. The code that created the session remains responsible for final
disposal.

## Current boundary

The first runtime slice has one synchronous initial scene and button actions.
Scene transitions, async loading, gesture mapping, viewport input conversion,
ECS, physics, assets, audio, and haptics are later work.

See the
[research document](https://github.com/OrekuD/react-native-gamekit/blob/main/REACT_NATIVE_GAMEKIT_RESEARCH.md)
for the full architecture direction.
