Camera2D is the opt-in camera system: a world larger than the screen, a view that follows a player, zoom and rotation, and touches that stay aligned with what you see. When no camera is configured, Gamekit behaves exactly as it always did — the camera composes before the existing viewport, never instead of it.

## The three spaces

The camera sits between authored positions and the screen:

```text
world point -> camera transform -> logical view point -> viewport -> surface
```

- **World space** holds authored positions, collision geometry, and camera targets.
- **Logical view space** is the region of the world the camera shows, an `Aabb2D` (for a 320 x 480 game, `{ x: 0, y: 0, width: 320, height: 480 }`).
- **Surface space** is React Native layout and native touch coordinates.

The forward transform is `logical = L + rotate(P - C, -R) * Z`, where `C` is the camera center, `Z` the zoom, `R` the rotation, and `L` the logical view center. The inverse reverses the same operations in reverse order, and the same pure functions back rendering and pointer input, so they cannot drift apart.

```ts
import { createCamera2D, worldToLogical2D, logicalToWorld2D } from 'rn-gamekit/camera2d';

const camera = createCamera2D({ center: { x: 100, y: 200 }, zoom: 2 });
const logical = worldToLogical2D({ x: 105, y: 195 }, camera, LOGICAL_VIEW);
const world = logicalToWorld2D(logical, camera, LOGICAL_VIEW); // round trip
```

Rotation is in radians, positive per the Skia convention. Zoom is a finite number greater than zero. Camera values are immutable plain data: no Skia matrices, no shared values, no mutable controllers. `createCamera2D()` defaults missing or `undefined` fields to center `(0, 0)`, zoom `1`, and rotation `0`. Explicit `null` fields are invalid and throw `GeometryError`. A selector must return a complete camera; its output never receives constructor defaults.

## Identity and the no-camera path

With no `camera2D` prop, `GameView`, `GameWorld2D`, and `GamePointerInput` retain viewport-only transforms. The identity camera that reproduces that path has its center at the logical view center, zoom 1, and no rotation. The no-camera display callback skips camera interpolation and its shared-value reads.

## One authoritative binding

The camera definition is static and lives on `GameView` only:

```tsx
import { defineGameCamera2D } from 'rn-gamekit/react';

const camera = defineGameCamera2D({
  select: (frame) => frame.current.camera,
});

<GameView game={game} renderer={PlatformRenderer} camera2D={camera}>
  <GamePointerInput game={game} action="move" />
</GameView>
```

`GameView` evaluates `select` and `cut` on the RN runtime at each commit, validates and copies the selected camera, then publishes the accepted frame and camera endpoints together in one UI task. Display callbacks interpolate with the renderer's alpha clock. The pointer adapter reads that same presented camera from the mounted surface. React updates once for initial camera readiness, never for each camera movement.

Before the first valid camera reaches UI, the renderer stays unmounted and new pointer begins are rejected. A rejected begin cannot become a drag later; the user must begin a new touch after readiness. Replacing the session or presentation creates a separate camera value so the new renderer cannot inherit the old session's transform.

## Cuts and interpolation

Center and zoom interpolate linearly; rotation takes the shortest arc. The presented `CameraCut2D` carries a `cutId` that increases across presentation replacements within a mounted `GameView`, and a new id snaps instead of interpolating. Cuts happen automatically on scene transitions, session replacement, and binding changes, and explicitly through the optional `cut` predicate for teleports and respawns. Pausing freezes interpolation; resuming never interpolates through background time. A valid scene cut still publishes while paused. Replacing the camera definition immediately reselects the latest attempted frame without restarting the session or waiting for another tick.

## Failed selection and recovery

If `select`, `cut`, or validation fails, the last valid frame, interpolation fraction, and camera remain visible together. The simulation continues unless your application pauses it. The next valid commit snaps to the latest frame and camera; it does not interpolate across the failed interval. If there has never been a valid camera, the renderer remains unmounted.

Use the optional reporter to observe a failure:

```ts
import { defineGameCamera2D, type GameCameraErrorInfo } from 'rn-gamekit/react';

const reportCameraError = ({ phase, error, scene }: GameCameraErrorInfo) => {
  console.error('Camera selection failed', { phase, error, scene });
};

const camera = defineGameCamera2D({
  select: (frame: GameFrame) => frame.current.camera,
  onError: reportCameraError,
});
```

Here `GameFrame` is your game's commit-frame type. `phase` is `select`, `cut`, or `validate`; `error` preserves the original thrown value as `unknown`. The reporter runs on RN at most once per uninterrupted failure episode, even if subsequent errors have different messages. A successful commit resets reporting. Exceptions thrown by the reporter are contained. Omitting it keeps the same fallback silently.

## Behavior helpers

The follow, bounds, and shake helpers are pure and headless — games call them inside the scene update and store the returned camera in scene state:

```ts
import { clampCameraBounds2D, followCamera2D, sampleCameraShake2D } from 'rn-gamekit/camera2d';

const followed = followCamera2D(camera, player, { deadZone: { x: -60, y: -80, width: 120, height: 160 } });
const clamped = clampCameraBounds2D(followed, WORLD_BOUNDS, LOGICAL_VIEW);
const shaken = sampleCameraShake2D(clamped, { seed: 7, elapsedSeconds: t, durationSeconds: 0.3, amplitude: 4 });
```

`followCamera2D` supports direct follow, an axis-aligned dead zone, per-axis follow, and a damping half-life. `clampCameraBounds2D` keeps the visible region inside a world bound (conservative for rotated views, centering axes where the world is smaller than the view). `sampleCameraShake2D` is deterministic from its seed. Its offset magnitude is at most `amplitude * (1 - elapsedSeconds / durationSeconds)` during the effect, and it returns the unmodified base camera at its duration. Because the shake lives in the presented camera, pointer inversion stays aligned with what the player sees.

## Layers, parallax, and culling

`GameLayer2D` renders ordered layers with per-axis parallax; the [Render layers](../guides/render-layers) guide covers the policy. Visibility is presentation-only: `getCameraVisibleBounds2D`, `intersectsCameraView2D`, and `filterCameraVisible2D` compute what the camera sees, and `SpriteBatch` can hide off-screen slots without touching the simulation. Off-screen entities keep moving, colliding, and re-entering view.

Passing `GameView`'s primary camera to `SpriteBatch.cull` does not account for a surrounding `GameLayer2D`'s parallax. In non-default parallax layers, omit `cull` unless you supply a camera matching that layer's effective transform.
