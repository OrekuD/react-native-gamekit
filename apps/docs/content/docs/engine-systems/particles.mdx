---
title: Particles
description: "Seeded, bounded sprite and shape bursts driven by committed events — fixed pools, analytic sampling, and presentation-only rendering."
---

Particles let you add juice — brick bursts, impact sparks — without letting visuals touch gameplay authority. A burst is a presentation-only reaction to a committed fact: the same definition, emission command, and seed always produce the same count, slot selection, lifetimes, velocities, and overflow choices.

## Package boundary

Particles are the `rn-gamekit/particles` subpath; rendering lives in `rn-gamekit/react`.

```ts
import { createParticleSystem, defineParticleEffect } from 'rn-gamekit/particles';
```

Importing `rn-gamekit` never starts a particle clock or allocates a pool. Definitions are validated immutable plain values — no Skia images, shared values, refs, or functions. Unused systems do zero work: nothing runs until `emit()` is called and a renderer advances the clock.

## Defining an effect

```ts
import { defineParticleEffect } from 'rn-gamekit/particles';

const brickBurst = defineParticleEffect({
  capacity: 96,
  space: 'world',
  overflow: 'recycle-oldest',
  particle: {
    kind: 'sprite',
    sheet: assets.effects.sheet,
    frame: 'spark',
    size: { width: 8, height: 8 },
  },
  burst: { count: 12 },
  lifetimeSeconds: { min: 0.25, max: 0.55 },
  speed: { min: 70, max: 150 },
  gravity: { x: 0, y: 180 },
  fadeOut: true,
});
```

Validation rejects invalid definitions eagerly: capacity must be an integer in `[1, 1024]`, ranges must be finite with `min ≤ max`, `burst.count ≤ capacity`, and `space`/`overflow`/`particle.kind` are exact unions. Shape particles support only `circle` (with optional `radius`) and `rectangle` (with optional `width`/`height`) plus one `color`.

## Creating the system

```ts
import { createParticleSystem } from 'rn-gamekit/particles';

const particles = createParticleSystem({ effects: { brickBurst } });
```

One mounted system owns fixed slot storage per effect, allocated exactly once at capacity. Capacity never grows at runtime.

## Emission from committed events

```ts
import { seedGameEvent } from 'rn-gamekit';

session.addGameEventListener('brick-hit', (event) => {
  particles.emit('brickBurst', {
    position: event.payload.point,
    seed: seedGameEvent(event),
  });
});
```

The seed drives a documented deterministic PRNG (mulberry32). Field consumption order is fixed: lifetime → speed → direction → rotation → rotation speed → scale start. The same command and seed therefore reproduce the same burst byte-for-byte within floating-point tolerance (`1e-4`). Never use `Math.random()` for seeds — event identity `(tick, ordinal)` is stable across catch-up replay.

Invalid commands throw before any pool mutation: unknown effect names, non-finite positions, non-finite seeds.

## Overflow policies

When every slot in the pool is active:

- `drop-new` ignores the new particle and counts it in diagnostics.
- `recycle-oldest` reuses the slot with the smallest spawn sequence and resets every field — origin, velocity, rotation, scale, opacity, color, sequence.

Tie-breaking is spawn sequence then slot index, so recycling order is stable under catch-up bursts.

## Analytic sampling

Position is closed-form from age, never accumulated per frame:

```text
position(age) = origin + velocity·age + ½·acceleration·age²
rotation(age) = initial + angularSpeed·age
opacity(age)  = fadeOut ? 1 − t : 1      where t = min(age / lifetime, 1)
scale(age)    = lerp(scaleStart, scaleEnd, t)
```

Equal active age produces identical sampled values regardless of how updates were scheduled — one 0.3s update equals three 0.1s updates within tolerance. Pause freezes age with no suspended wall-time debt; resume continues at the same age. Culled particles keep aging: culling changes visibility only.

## One clock per system

A system has exactly one presentation owner. `useParticlePresentation(system)` acquires the binding's exclusive driver lease (a second owner throws deterministically) and runs the only rAF loop; while the lease is held, ad-hoc `tick()` calls are rejected so nothing can double-advance age. The loop fully stops when every slot is idle and restarts on the next accepted emission. Two independent pause sources are honored: the session status reader AND an optional `manualPaused` callback — a running session can never cancel a manual pause. Each changed revision is published as fresh plain arrays, so the UI runtime always observes the latest frame.

## Lifecycle

- Session pause freezes the clock; emissions while paused drop their whole burst into `dropped`.
- Invalid effect names or malformed commands always throw — even while paused.
- Disposal clears slots and rejects new work; it is idempotent.
- Old-session events cannot emit into a replacement controller — dispose the old system when its session retires.
- Unmounting the presentation hook stops the driver; idle ticks write nothing.

Diagnostics semantics are per particle: `emitted` counts placed particles (fresh or recycled), `dropped` counts never-placed particles (overflow under `drop-new` plus whole paused bursts), and `recycled` counts placed particles that reused an occupied slot. They are immutable snapshots read at control frequency (~8Hz).

## Rendering

Storage is sized from the effect's immutable capacity — never a global maximum.

**Shapes** render through ONE immediate `Picture` rebuilt on the UI runtime from the published frame: one React component and one worklet per effect regardless of capacity — no per-slot nodes exist. Circles draw at sampled centers with scaled radii; rectangles translate→rotate→scale around their center.

**Sprites** render through a fixed-capacity `Atlas` batch following the SpriteBatch buffer pattern: source rects resolve once at bind time from the caller-provided decoded sheet, and one UI-runtime derived value writes all transforms — with sampled scale folded into the RSXform (`scos = s·cosθ`) and center-anchor pivot compensation against the authored size. v1 requires the authored size aspect to match the source frame aspect; mismatches throw at bind time. A sprite effect rendered without its resolved `spriteSource` also throws a structured error instead of silently drawing nothing.

World-space effects must be mounted inside the matching `GameWorld2D` so the presented camera + viewport transform applies exactly once; culling computes conservative world AABB from the camera's actual center/zoom/rotation plus padding (shared by both render paths). Screen-space effects bypass the camera and cull against surface bounds. Culled particles keep aging — visibility never feeds back into the clock.
