---
title: Sprite Batching
description: Draw hundreds of repeated sprites with an Atlas-backed batch.
---

`SpriteBatch` renders many instances of one decoded sprite sheet through
Skia's `Atlas` with fixed-capacity, UI-owned buffers. It is the explicit
tool for shared-texture density — retained `Sprite`s are for a stable,
modest number of independently authored sprites. Gamekit never switches
between the paths automatically; authors choose, and the docs explain the
trade-off with measured data.

```tsx
import { SpriteBatch } from 'rn-gamekit/react';

<SpriteBatch
  scene="play"
  commit={frame}
  alpha={alpha}
  source={assets.get(gameAssets.gameplay.enemies)}
  capacity={512}
  select={({ current }) => {
    'worklet';
    return current.enemies;
  }}
  write={(write, enemy, index) => {
    'worklet';
    write.set(index, enemy.frame, enemy.x, enemy.y, enemy.rotation, enemy.scale, enemy.visible);
  }}
/>
```

## Contract

- `capacity` is fixed for the mounted batch; active count is explicit.
- The batch owns its UI reaction: `select` maps the committed snapshot to
  items and `write` updates slots. After writing the slots, the batch
  publishes the buffers to Skia. Authors need no frame callback or manual
  refresh. Both callbacks must be worklets.
- Buffers stay allocated at capacity; updates do not render React. Selection,
  update policy, and transform calculations can still allocate temporary
  values, so fixed buffers do not imply zero per-frame allocation.
- `write.set(index, frame, x, y, rotation, scale, visible)` — writes past
  capacity fail clearly in development; inactive slots are hidden with
  zero-size rects and never remount topology.
- Item order is the drawing order; the anchor is uniform per batch.
- The batch never disposes the image — the asset lease owns it.
- Do not put unrelated textures in one batch; multiple sheets may share a
  batch only if they resolve to the same Skia image.

## When not to batch

- A handful of unique sprites: use retained `Sprite`s.
- Mixed textures in one draw: use separate batches.
- Per-sprite non-uniform scale: the RSXform carries uniform scale only;
  retained sprites support non-uniform scale through the wrapping group.

## Performance evidence

Use the Performance Lab's sprite-scaling scenario to compare retained and
batched rendering on representative physical devices. Buffer publication
tests check update ordering and notifications; they do not measure FPS or
establish a universal count at which batching becomes faster.
