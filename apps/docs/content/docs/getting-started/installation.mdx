You'll need an Expo project and a few minutes. By the end of this page you'll have a native dev build running React Native Gamekit, ready for your first scene.

## Requirements

React Native Gamekit is validated against one compatibility line, and the playground exercises that exact line on iOS, iPadOS, and Android:

| Dependency | Version |
| --- | --- |
| Expo | SDK 57 (`~57.0.25`) |
| React Native | `0.86.3` |
| React | `19.2.3` |
| React Native Skia | `2.11.0` |
| React Native Gesture Handler | `~3.1.0` |
| React Native Reanimated | `4.5.3` |
| React Native Worklets | `0.10.3` |
| Expo Asset | `~57.0.18` |

## Install the native peers

Gamekit doesn't ship native code. Skia, Gesture Handler, Reanimated, Worklets, and Expo Asset are native modules that your app owns, and Gamekit declares the exact version line it was validated against. Your app ends up with exactly one copy of each native module, which is what native modules want.

Pin the validated line so you don't drift to the SDK template versions:

<Tabs items={['npm', 'yarn', 'pnpm', 'bun']} groupId="package-manager" persist>
  <Tab value="npm">
    ```sh
    npx expo install @shopify/react-native-skia@2.11.0 react-native-gesture-handler@~3.1.0 react-native-reanimated@4.5.3 react-native-worklets@0.10.3 expo-asset@~57.0.18
    ```
  </Tab>
  <Tab value="yarn">
    ```sh
    yarn expo install @shopify/react-native-skia@2.11.0 react-native-gesture-handler@~3.1.0 react-native-reanimated@4.5.3 react-native-worklets@0.10.3 expo-asset@~57.0.18
    ```
  </Tab>
  <Tab value="pnpm">
    ```sh
    pnpm expo install @shopify/react-native-skia@2.11.0 react-native-gesture-handler@~3.1.0 react-native-reanimated@4.5.3 react-native-worklets@0.10.3 expo-asset@~57.0.18
    ```
  </Tab>
  <Tab value="bun">
    ```sh
    bunx expo install @shopify/react-native-skia@2.11.0 react-native-gesture-handler@~3.1.0 react-native-reanimated@4.5.3 react-native-worklets@0.10.3 expo-asset@~57.0.18
    ```
  </Tab>
</Tabs>

Skia, Gesture Handler, Reanimated, and Worklets are intentionally ahead of the SDK 57 template, so exclude them from Expo's version check in your `package.json`. Don't run `npx expo install --fix` without this exclude — it downgrades them to the template line and breaks input and rendering. See the [Expo package.json reference](https://docs.expo.dev/versions/latest/config/package-json/#installexclude) for the `expo.install.exclude` field.

Importing `rn-gamekit` does not load these backends. Calling `createGameAudio()` or `createGameHaptics()` without the peer throws `is not installed — run npx expo install ...`.

### Optional persistent storage peer

The memory storage adapter has no native dependency. Install AsyncStorage only
if you use `createGameStorageAdapter()` for persistent saves:

```sh
npx expo install @react-native-async-storage/async-storage@2.2.0
```

## Generate the native projects

Expo Go can't run this. Gamekit needs the Skia, Gesture Handler, and Reanimated runtimes, which are native modules, so you need a development build. Generate the iOS and Android projects with:

```sh
npx expo prebuild
```

The `ios` and `android` folders are generated, so keep them out of version control. Change native configuration through `app.json` and config plugins, then regenerate. Expo calls this Continuous Native Generation (CNG), and it's the workflow the playground itself uses.

## Wrap the app root

Gesture Handler needs the root of your component tree wrapped in `GestureHandlerRootView`:

```tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';

export default function App() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      {/* your game goes here */}
    </GestureHandlerRootView>
  );
}
```

## Run the dev build

```sh
npx expo run:ios     # iOS simulator
npx expo run:android # Android emulator
```

The first build compiles the native modules, so give it a few minutes. Later builds are fast.
