You're going to build a tiny paddle game. A ball bounces around a 320 by 180 world, your finger moves the paddle, and missing the ball resets it to the middle. It's small enough to read in one sitting and it touches every part of the runtime: a game definition, a scene, pointer input, a renderer, and the React mount.

By the end you'll have something playable on your device, not just a screen with a circle on it.

## 1. Set up your project

If you haven't already, follow [Installation](./installation) to create an Expo project with a dev build and `rn-gamekit` installed. This tutorial assumes you're there.

## 2. Define the game

A game definition is static data: a viewport, the input actions your game declares, and the scenes it can show. Creating it allocates no runtime state.

```ts
// game.ts
import { defineGame, defineScene } from 'rn-gamekit';

const WIDTH = 320;
const HEIGHT = 180;
const PADDLE = { width: 48, height: 10, y: 164 };
const BALL = { radius: 6 };

export const paddleGame = defineGame({
  viewport: {
    logicalSize: { width: WIDTH, height: HEIGHT },
    mode: 'fit',
  },
  input: {
    steer: { type: 'pointer', description: 'Move the paddle' },
  },
  scenes: {
    play: playScene,
  },
  initialScene: 'play',
});
```

The viewport declares the logical world your game thinks in. `fit` scales that world to whatever screen it lands on, letterboxing when the aspect ratios differ. Input actions are semantic names, not raw events: the game says "steer", and the platform decides how fingers become steers.

## 3. Write the play scene

A scene owns its state and decides how it changes every tick. Gamekit runs a fixed step: the same simulation, at the same speed, on any device.

```ts
// game.ts
const playScene = defineScene({
  actions: ['steer'],
  create: () => ({
    paddleX: WIDTH / 2,
    ball: { x: WIDTH / 2, y: HEIGHT / 2, vx: 90, vy: 70 },
  }),
  update: ({ state, input, deltaSeconds }) => {
    const steer = input.pointer('steer');

    // The pointer position is already in logical world coordinates.
    // Clamp the paddle so it can't leave the world.
    const paddleX =
      steer.active && steer.position !== undefined
        ? Math.min(Math.max(steer.position.x, PADDLE.width / 2), WIDTH - PADDLE.width / 2)
        : state.paddleX;

    let { x, y, vx, vy } = state.ball;
    x += vx * deltaSeconds;
    y += vy * deltaSeconds;

    // Bounce off the side walls and the ceiling.
    if (x - BALL.radius <= 0 || x + BALL.radius >= WIDTH) vx = -vx;
    if (y - BALL.radius <= 0) vy = -vy;

    // Bounce off the paddle, only when the ball is on its row.
    const onPaddleRow = y + BALL.radius >= PADDLE.y && y + BALL.radius <= PADDLE.y + PADDLE.height;
    if (onPaddleRow && x >= paddleX - PADDLE.width / 2 && x <= paddleX + PADDLE.width / 2) {
      vy = -Math.abs(vy);
    }

    // Missed: put the ball back in the middle.
    if (y - BALL.radius > HEIGHT) {
      return { paddleX, ball: { x: WIDTH / 2, y: HEIGHT / 2, vx: 90, vy: 70 } };
    }

    return { paddleX, ball: { x, y, vx, vy } };
  },
});
```

The update receives the previous state and returns the next one. That's the whole model: `state` in, `state` out, nothing else mutated. `input.pointer('steer')` gives you the sampled pointer: whether it's `active`, its logical `position`, and one-tick edges like `pressed`. `deltaSeconds` is the constant fixed-step duration, so movement math stays the same at any frame rate.

## 4. Snapshot what the renderer should draw

The renderer never sees your scene state. Each tick you hand it a small snapshot, which keeps the presentation side free to change without touching the simulation.

```ts
// game.ts
const playScene = defineScene({
  actions: ['steer'],
  create: () => ({ ... }),
  update: ({ ... }) => { ... },
  snapshot: ({ state }) => ({
    paddle: { x: state.paddleX, y: PADDLE.y, width: PADDLE.width, height: PADDLE.height },
    ball: { x: state.ball.x, y: state.ball.y, radius: BALL.radius },
  }),
});
```

The final `game.ts` declares the scene before the definition, because the definition references it. The assembled file order is: constants, scene, definition.

## 5. Draw it with Skia

The renderer is a React component that reads the committed snapshot and draws in logical coordinates. The viewport shared value supplies the scale and letterbox offset, so drawing and touch hit-testing always agree. The shared values are passed to Skia directly, so they re-evaluate on the UI runtime without triggering React re-renders:

```tsx
// Renderer.tsx
import { Circle, Rect } from '@shopify/react-native-skia';
import { useDerivedValue } from 'react-native-reanimated';
import type { GameRendererProps } from 'rn-gamekit/react';
import { paddleGame } from './game';

export function PaddleRenderer({
  frame,
  viewport,
}: GameRendererProps<typeof paddleGame['scenes']>) {
  const paddleX = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.paddle.x * surface.scale + surface.offsetX;
  });
  const paddleY = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.paddle.y * surface.scale + surface.offsetY;
  });
  const paddleWidth = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.paddle.width * surface.scale;
  });
  const paddleHeight = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.paddle.height * surface.scale;
  });

  const ballX = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.ball.x * surface.scale + surface.offsetX;
  });
  const ballY = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.ball.y * surface.scale + surface.offsetY;
  });
  const ballRadius = useDerivedValue(() => {
    const surface = viewport.value;
    const value = frame.value;
    if (surface === undefined || value.scene !== 'play') {
      return 0;
    }
    return value.current.ball.radius * surface.scale;
  });

  return (
    <>
      <Rect x={paddleX} y={paddleY} width={paddleWidth} height={paddleHeight} color="#334155" />
      <Circle cx={ballX} cy={ballY} r={ballRadius} color="#0ea5e9" />
    </>
  );
}
```

`frame` holds the latest committed snapshot. It's a shared value, so the renderer reads it on the UI runtime without triggering React re-renders. If you ever want buttery motion between commits, the `alpha` prop interpolates between the previous and current snapshots; the Brick Breaker walkthrough shows that pattern.

## 6. Mount the game

Hand the definition to `useGameSession` and let `GameView` present it:

```tsx
// App.tsx
import { StyleSheet, View } from 'react-native';
import { GestureHandlerRootView } from 'react-native-gesture-handler';
import { GamePointerInput, GameView, useGameSession } from 'rn-gamekit/react';
import { paddleGame } from './game';
import { PaddleRenderer } from './Renderer';

export default function App() {
  const session = useGameSession(paddleGame);

  if (session === undefined) {
    return null;
  }

  return (
    <GestureHandlerRootView style={styles.root}>
      <GameView game={session} renderer={PaddleRenderer} style={StyleSheet.absoluteFill}>
        <GamePointerInput game={session} action="steer" />
      </GameView>
    </GestureHandlerRootView>
  );
}
```

The hook owns creation and terminal disposal, and it's safe under Strict Mode: every development rehearsal session is disposed exactly once, and a disposed session is never returned. `undefined` means React hasn't committed a live session for the definition yet, which happens on the first render and while a definition replacement is being created. Rendering `null` for that frame is the deliberate fallback.

`GameView` borrows the session: it starts it while mounted, pauses it when the app backgrounds, and never terminally disposes it. Because the hook owns disposal, don't call `session.dispose()` on a hook-owned session. For headless tests and non-React owners, `createGameSession()` with an explicit `try/finally` dispose remains the imperative path.

Once it's playable, freeze it: the [Pause and resume](../guides/pause-and-resume) guide shows a pause overlay built from `useGameSessionStatus` — one press pauses, one resumes, and the last frame stays visible.

## 7. Run it

```sh
npx expo run:ios
```

Drag anywhere on the screen. The paddle follows your finger, the ball bounces, and a miss puts the ball back in the middle. That's a game loop, pointer input, a viewport, a renderer, and a session lifecycle, all working together.

## The boundary that matters

Notice what never happened: no `useState` for the paddle, no re-renders per frame, no React anywhere near the simulation. The game runs headless at a fixed step; React only presents the latest snapshot. That boundary is the whole design of React Native Gamekit, and it's what makes the simulation deterministic and testable. Every concept page from here builds on it.
