This is the direction of travel, not a schedule. Every system below lands only when a reference game needs it and the headless-first boundary survives the addition. The [Changelog](../changelog) is the source of truth for what actually landed.

## Recent additions

- **Camera2D** (see [Engine Systems](../engine-systems/camera2d)): one authoritative presented camera shared by rendering and pointer input, with follow, world bounds, cuts, deterministic shake, parallax layers, and visibility culling.
- **Collision2D** (see [Collision2D](../engine-systems/collision2d)): geometry primitives, contact manifolds, swept queries, segment crossings, category/mask filters, a deterministic spatial hash broad phase, and headless debug projection.
- **Game events** (see [Events](../engine-systems/events)): declared event names, typed envelopes with payload limits, deterministic seeding, and update-scoped emitters.
- **Particles** (see [Particles](../engine-systems/particles)): headless effect definitions and simulation with presentation-only Skia rendering and camera-aware culling.
- **Audio and haptics** (see [Audio](../engine-systems/audio) and [Haptics](../engine-systems/haptics)): opt-in subpath entries with lifecycle-aware playback and bounded haptic presets.
- **Tilemaps** (see [Tilemaps](../engine-systems/tilemaps)): chunked authored
  maps, bounded queries, Atlas rendering, Tiled imports, and platformer
  movement helpers.
- **Storage** (see [Storage](../engine-systems/storage)): versioned save
  projections, bounded serialization, migrations, ordered writes, and an
  optional persistent adapter.

## Next up

- **Scene transition payloads.** Scenes can already switch (`transition.setScene`), but they can't pass results. Brick Breaker works around this by keeping the win state inside the play scene; payloads would let a results screen read the score directly.
- **Keyboard and gamepad input.** One primary pointer exists today. Keyboard and controller support would open up desktop-style games on iPad and Android tablets.

## Further out

- **Physics.** Optional rigid-body integration remains deferred. Collision2D
  continues to provide deterministic detection without defining the game's
  world model.
- **3D rendering.** The architecture keeps future seams open, but the public
  package remains focused on 2D.

## Infrastructure

- **TypeDoc pipeline.** The manual [API Reference](../api/components) pages move to generated documentation once the public surface stabilizes.
- **Web renderer.** Not planned for the runtime; the docs site is the only web surface.

## What will not change

The headless-first boundary is the design, not a phase. Game state advances through the session, never through React re-renders, and every future system keeps its simulation headless with a renderer adapter on top. Proposals that break that boundary are rejected before they reach the plan.
