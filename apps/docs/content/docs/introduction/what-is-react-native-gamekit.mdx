---
title: What is react native gamekit
description: A headless 2D game toolkit for React Native and Expo.
---

react native gamekit is a headless 2D game toolkit for React Native and Expo. You define a game as data, a session runs it deterministically at a fixed step, and Skia presents the result.

## A game is a definition

You describe a game once with `defineGame`: a viewport, the input actions it declares, and the scenes it can show. A definition is plain configuration, fully typed, and safe to keep at module scope. Creating it allocates no runtime state.

```ts
import { defineGame, defineScene } from 'rn-gamekit';

const game = defineGame({
  viewport: { logicalSize: { width: 320, height: 180 }, mode: 'fit' },
  input: {
    steer: { type: 'pointer', description: 'Move the paddle' },
  },
  scenes: {
    play: defineScene({
      actions: ['steer'],
      create: () => ({ x: 0 }),
      update: ({ state, input }) => {
        const steer = input.pointer('steer');
        return steer.active && steer.position !== undefined ? { x: steer.position.x } : state;
      },
      snapshot: ({ state }) => ({ x: state.x }),
    }),
  },
  initialScene: 'play',
});
```

A scene owns its state and decides how it changes every tick. Each update receives the previous state and returns the next one, nothing else mutates, and the result is a small snapshot the renderer can draw.

## A session runs it headlessly

`useGameSession(game)` creates a live session and owns its disposal, or `createGameSession(game)` does the same imperatively for tests and non-React code. The session advances at a fixed step, so a phone presenting at 60 Hz and an iPad at 120 Hz run the same number of simulation ticks in the same wall time. The whole simulation runs in plain JavaScript and drives identically in Node tests and on a device.

## React only presents

`GameView` borrows the session and presents its commits through your Skia renderer; `GamePointerInput` feeds touches in through the same viewport the renderer draws with. Positions and tick counters live in shared values on the UI runtime, never in React state. React re-renders only when something static changes, like the HUD.

```tsx
import { GamePointerInput, GameView, useGameSession } from 'rn-gamekit/react';

function GameScreen() {
  const session = useGameSession(game);

  if (session === undefined) {
    return null;
  }

  return (
    <GameView game={session} renderer={MyRenderer}>
      <GamePointerInput game={session} action="steer" />
    </GameView>
  );
}
```

## One package, many entry points

`rn-gamekit` is one npm package. The paths below are package export subpaths — not separate packages. They share one version, one peer-dependency policy, and one `exports` map, and they all ship in the same tarball. One `npm install rn-gamekit` is enough.

| Entry point | What lives there | Must not load |
| --- | --- | --- |
| `rn-gamekit` | Game & scene definitions, session, viewport, and compatibility re-exports | — |
| `rn-gamekit/geometry` | Points, vectors, AABBs, circles, segments, `GeometryError` | React / Skia / native |
| `rn-gamekit/collision2d` | Predicates, manifolds, sweeps, filters, colliders, spatial hash, debug | React / Skia |
| `rn-gamekit/camera2d` | Pure camera values, transforms, follow, clamp, shake, interpolation, visibility | React / Skia |
| `rn-gamekit/events` | `defineGameEvents` / `gameEvent`, envelopes, `PAYLOAD_LIMITS`, `seedGameEvent`, `GameEventError` | React / native |
| `rn-gamekit/assets` | `defineAssets` / `image` / `spriteSheet`, descriptor types, `GameAssetError` | React / Skia |
| `rn-gamekit/sprites` | `sampleSpriteClip*`, `start/advance/…SpriteAnimation` | React components / Atlas |
| `rn-gamekit/react` | `GameView`, `GameWorld2D`, `Sprite`, hooks, asset/particle/tilemap rendering | — |
| `rn-gamekit/audio` · `haptics` · `particles` · `tilemap` | Opt-in or existing system subpaths | — |
| `rn-gamekit/testing` | Deterministic frame driver (test-only) | — |

Headless entries import no React, React Native, Skia, Reanimated, or Expo Asset. `rn-gamekit/react` is the only entry that loads the native renderer.

**Preferred imports**

```ts
import type { Aabb2D } from 'rn-gamekit/geometry';
import { collideCircleAabb2D } from 'rn-gamekit/collision2d';
import { createCamera2D } from 'rn-gamekit/camera2d';
import { defineGameEvents, gameEvent } from 'rn-gamekit/events';
import { defineAssets, image, spriteSheet } from 'rn-gamekit/assets';
import { sampleSpriteClipFrame, startSpriteAnimation } from 'rn-gamekit/sprites';
import { GameView, GameWorld2D } from 'rn-gamekit/react';
```

**Compatibility:** `import { collideCircleAabb2D } from 'rn-gamekit'` and other existing root imports continue to work. Root and subpath exports are the same symbols (`===`, `instanceof` preserved). No deprecation is announced in this release — the subpaths are the preferred organization, not a breaking change.

## What's included

- Fixed-step headless sessions with named scenes and deterministic transitions
- Button and pointer input with ownership and edge sampling
- Three viewport modes with shared surface-to-world math
- Sprites, sprite sheets, animation clips, and Atlas-backed batching
- Typed local asset manifests with reference-counted loading
- A `Camera2D` system with follow, shake, bounds, culling, and parallax layers
- 2D collision detection with shapes, sweeps, manifolds, and a spatial hash
- Headless particle effects with presentation-only Skia rendering
- Audio playback and haptic patterns through opt-in subpath entries
- A `testing` entry with a manual frame driver for deterministic tests

## What it isn't yet

There's no physics simulation or ECS layer, and tilemaps and 3D are future work. Input beyond buttons and pointers (keyboard, gamepad, virtual sticks) is not covered yet; see the [Roadmap](./roadmap) for what's coming and what order it lands in.
